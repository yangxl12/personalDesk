## 修复：dev server 报「数据服务暂不可用」(503 DATABASE_UNAVAILABLE)

- 现象：`/login` 返回 500，之后全站 503；dev 日志 `Database worker failed Unsupported SQLite version: 3.51.2`。

- 环境注意：本机 PATH 上 `C:\Program Files\Volta\node.exe` 是 v22.22.2 且优先级高，`C:\nvm4w\nodejs` 是 v24.18.0。日常终端可能命中的是 Volta 的 22.22.2，导致复发。建议用 `volta pin node@24.18.0` 固化，或在终端先 `nvm use 24.18.0`。

## 14:30 修复：目标卡片一张占满轨道，相邻卡片完全被裁掉

- 现象（龙哥手机端）：多目标时只看得到一张卡，左右看不到相邻卡片的边，完全看不出还能横向滑动。实测根因：`.goal-slide` 手机 `flex: 0 0 100%`，下一张起点 = 轨道右边缘 +7px（gap），整块被 `overflow` 裁掉；桌面 `0 0 50%` 正好塞满两张，第 3 张同样零提示。
- 改法（`src/app.css`）：抽出 `--gap: calc(var(--gutter)/2)` 与 `--peek`；手机端 `.goal-slide` 宽 `calc(100% - (var(--peek) + var(--gap))*2)` + `scroll-snap-align: center`，并用 `.goal-board::before/::after {content:''; flex:0 0 var(--peek)}` 补首尾留白，卡片才能真居中且前后各露 22px；桌面 `--peek:36px`、隐掉伪元素、宽 `calc((100% - var(--gap)*2 - var(--peek))/2)` 保持两张并排 + 右侧露第三张 36px。
- 数学关系（推导过，改数值别乱动）：首尾留白 = `--peek` 时，左右露出的宽度都正好等于 `--peek`；卡片宽必须减去 `(peek+gap)*2` 才能保持居中。
- 验证：dev + 临时 `DATA_DIR` 起 6183，直接 import `tests/e2e/dashboard.py` 的 `verify_dashboard` 实跑通过（桌面 1440 / 手机 390，pageerrors 为空）；另截图核对 390/761/820/1000/1280/1440 六个宽度。手机实测：卡片 304 居中、左右各露 22px、gap 7px；桌面：两张 525 + 右侧 36px。
- `tests/e2e/dashboard.py`：删掉「卡宽与财务卡片对齐」的旧断言，换成居中 + 左右露出（22/36px）断言，并在滑动到第二张后复位 `scrollTo({left:0})`，避免后续 tap 与 mandatory snap 打架。
