## 发现的问题

### BUG-01 · 登录页刚打开时快速提交可能丢失账号输入

**影响**：首次登录可停留在登录页，用户需要重新输入账号。已在 Windows Playwright WebKit 26.5 的 iPhone 13 模拟中确认，真实 iPhone Safari 尚待验证。

**复现步骤**

1. 用生产构建启动本地服务，创建临时账号。
2. 每次创建全新的 WebKit 浏览器上下文，使用 Playwright 的 `iPhone 13` 设备预设。打开首页，等待重定向到 `/login`。
3. 页面一出现就依次 `fill` 账号和密码，再点击或触屏点按「登录」。在提交前不主动等待 `networkidle`。监听 `POST /login` 并等待进入工作台。

| 预期 | 实际 |
| --- | --- |
| 账号保留，登录请求发出，凭据正确时进入工作台 | 5 次快速提交中，3 次点击和 2 次触屏点按均复现。填完密码时仍可读取账号，提交前账号变空，原生必填校验拦截，未观察到 `POST /login` |
| 对照测试 | 打开登录页后先等待 `networkidle` 再填写，2 次点击、2 次触屏点按、1 次回车均成功，均观察到登录请求并进入工作台 |

现象与登录表单的客户端初始化时序相关。输入被清空的具体原因尚未定位，涉及页面为 [登录表单](../src/routes/login/+page.svelte)。

## 复跑命令

从项目根目录运行，前置环境见 [README](../README.md)。端到端脚本会自行建临时账号、数据库并启动生产服务。

```bash
npm run check
npm test
npm run build
python -m pip install playwright==1.61.0
python -m playwright install chromium webkit
python tests/e2e/workspace.py
```

仓库端到端脚本默认运行 Chromium。WebKit 补测可按上文复现步骤运行。
